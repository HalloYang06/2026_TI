## 我实际使用的定位顺序

1. 先确认任务和链路状态：LCD 的任务号、M33 `READY/LINK/IMU`、电机是否已完成 B21 调平。没有 READY 时，不调 PID。

2. 只采一轮，保存完整日志：记录任务模式、视觉位置、管角、IMU、底盘速度/阶段、饱和标志和时间戳。先确认这一轮确实是 Q3/Q4/Q5/Q6，旧帧和错误模式的数据一律作废。

3. 先分域：启动不了属于状态机/传感器有效性；位置认错属于视觉；有输出但角度不动属于电机/CAN；能动但误差不收敛才属于控制器。

4. 看“控制要求”和“执行能力”是否一致。若管角已经顶在 ±2°，继续增大前馈或 Kp 没有意义；必须先承认是饱和、软启动或目标轨迹的问题。

5. 每次只改一个因子：例如只改 Q6 横向耦合，或只改 Q3 `Kd`。一次同时改前馈、滤波、角度限幅，会不知道变好或变坏是哪个造成的。

6. 每一小步都编译、烧录、跑一轮并提交。结果要量化为：最大误差、首次进入 ±1 cm 的时间、稳态偏差、最大超调、IMU 丢帧和状态机重试次数。

| 出弯时 Q6 偏差变大 | X/Y 加速度、管角是否饱和、球速度、轨迹阶段 | 转弯不是只看 X；纵向与横向加速度都要进模型。Q6 横向耦合目前为 0.50，Q4/Q5 为 0.25 | 只看单轴，或同时把耦合、滤波时间和管角上限都改大。此前这种组合在实车上变差，已撤回 |

## IMU 丢失：完整因果链

`WIT UART 输入速率 > 单周期处理量`，因此 RX 队列周期性积压；开始阶段 LCD 的阻塞初始化又放大首段积压。队列溢出后，解析器丢失字节边界，连续帧不可用，M33 的 IMU 有效位清掉，任务启动门拒绝 SW1。现场表现因此是“约一段时间一次 MISS，随后一段时间恢复”，不是 IMU 物理掉电。

修复后要同时确认：`dropped=0`、队列 high-water 没有贴近 1024、IMU 帧计数持续增长、M33 READY 正常。只看到某一帧 IMU 数据不等于链路已经稳定。

详细原始证据见 [IMU 丢失根因文档](imu-dropout-root-cause-and-fix-20260801.md) 和 [MISS/SW1 分析](imu-miss-sw1-debug-analysis-20260801.md)。

## Q3 和 Q4–Q6 不可混用的部分

Q3 是管道内的视觉位置 PID 扫动题：`Kp/Ki/Kd + 目标速度` 是主调节量，且需要 B21 预调平和人工放 O 点。

Q4–Q6 是行驶时的 LQI/状态估计控制：核心是位置、速度、积分、IMU 纵横向加速度补偿、底盘启动/转弯轨迹与管角饱和。不要把 Q3 的 `Kd` 结论照搬到 Q4–Q6，也不要把 Q4–Q6 的加速度前馈套到 Q3。

## 算法结构、参数含义与调参决策

### Q3：先把“轨迹”和“平衡点”调对，再调 PID

Q3 的控制思想是让球跟踪一个限速位置参考，而不是把 `+5 cm` 或 `-5 cm` 一步跳给电机。实际控制量可以概括为：

```text
管道角命令 = 调平角 + Kp × 位置误差 + Ki × 误差积分 + Kd × 误差变化率
```

其中目标位置以 `q3_rate_cms` 限速从 0 向 +5 cm、再向 -5 cm 移动。这样做的决策是：球的滚动系统有明显惯性和滞后，阶跃目标会使管角快速顶到限幅，产生“到点后还在冲”的假象；限速参考把问题从“追一个突变”改为“跟一条可执行轨迹”。

| 参数 | 它实际解决的问题 | 过小的现象 | 过大的现象 | 调整决策 |
| --- | --- | --- | --- | --- |
| 调平角 `level` | 重力的恒定偏置 | 不施加 PID 已自行向一侧滚，积分长期偏置 | 向另一侧滚 | 先 B21 调平；不能用 `Ki` 长期代偿明显的机械倾斜 |
| `q3_rate_cms` | 目标本身的激烈程度 | 太慢、时间可能不够 | 到端点时来不及制动、管角长期饱和 | 先选能完整走完路径的最大速度，再调 PID；当前为 20 cm/s |
| `Kp` | 位置误差的推动力 | 到不了目标、响应拖后 | 更易超调、早早打满角度 | 只在未饱和且确实“推不动”时增加 |
| `Ki` | 静摩擦、固定坡度、模型偏置 | 最后总停在目标一侧 | 末段慢摆、反向后继续推 | 只在球速接近零、管角未饱和的稳态误差上小幅增加 |
| `Kd` | 对球速的制动/阻尼 | 抵达 -5 cm 后冲到 -6 cm 再回来 | 响应钝、视觉噪声被放大 | 出现末段超调时优先增加；若变慢或抖动则退回 |

Q3 最终选择 `0.80 / 0.16 / 0.16` 与 20 cm/s，并不是理论全局最优，而是当前电机、管道、球和视觉条件下的实机折中：目标能到达，末段超调较历史高增益方案小。它仍依赖调平角正确；调平角从 1.72、1.60 到当前 1.75 rad 曾多次变化，说明这个值是机械安装相关的偏置，**不能假设换场地、重新装球或更换管道后仍是通用常数**。

当前尚未解决的是“自动学习水平角”：B21 只会回到设定角并等待稳定，不会利用视觉自动搜索让钢球静止的真实平衡角。若要做自动化，正确做法是空载/有球静止检测、以小角度扫动、依据持续球速/位置漂移最小化估计偏置，并给搜索范围、时间和角度限幅；不能在正式 Q3/Q4/Q5 运行时边滚边改平衡角。

### Q4–Q6：把静态误差、起步误差和转弯误差分开

Q4–Q6 的管角不是纯 PID。其核心是状态反馈加积分，再叠加底盘惯性补偿：

```text
管道角命令 = 平衡角
           + Kp × 位置误差
           - Kv × 球速度
           + Ki × 位置误差积分
           + 纵向加速度前馈
           + 横向加速度耦合
```

符号取决于传感器轴向和机械安装，日志要看“补偿后误差是否被抵消”，不要仅凭公式的正负号改方向。管角命令还受正式 ±2°、恢复/稳态等限幅约束，因此任何增益的有效性都要先看是否饱和。

| 误差类型 | 日志特征 | 首选调整对象 | 不该先调的对象 |
| --- | --- | --- | --- |
| 静态总差 1–2 cm，球速接近 0 | 误差同向、持续；无明显底盘加速度 | 调平角/该任务 `Ki`；先确认管角未打满 | 纵向加速度前馈 |
| 一启动就偏很大，随后能恢复 | 只发生在速度爬升段 | 底盘 S 曲线/软启动、IMU bias 锁定时刻、角度限幅连续性 | 静态 `Ki` |
| 直线加减速时总向一侧偏 | 与 Y 向加速度同相，收油后减轻 | 纵向加速度前馈及其滤波/偏置 | 横向耦合 |
| 出弯误差大 | 与 X、Y 向加速度及转弯段同相 | 横向耦合；必要时检查两个轴的坐标变换 | 只加大 `Kp` |
| 进入目标很快但来回摆 | 误差过零多次、球速度大 | 增大 `Kv` 或降低 `Kp` | 增大 `Ki` |
| 一直达不到目标但不摆 | 误差单向、积分小或角度打满 | 增大该任务 `Ki`；若已饱和则改平衡角/可执行轨迹 | 同时提高全部三个增益 |

这里的 `Kv` 是对球速度的阻尼项，作用相当于 Q3 的“制动思路”，但不是同一套 Q3 `Kd`。`Ki` 只消除低频固定偏差；它不能补偿加速瞬间，反而会在软启动结束后造成迟到的反向推力。

### 已做过的参数决策及原因

| 决策 | 依据 | 保留/撤回 |
| --- | --- | --- |
| Q4 的 LQI 参数和底盘起步曲线对齐 Q5 | Q5 是已观察到较稳定的直线/整圈基线，而 Q4 起步更容易偏 | 保留：Q4/Q5 都是 `2.20 / 1.60 / 0.05`，软启动 1.20 s |
| Q6 使用更高 `Kp`、更低 `Kv`、更高 `Ki` | Q6 在非零目标时长期低于目标，既需要位置推动也需要消除静态偏置 | 当前基线：`2.50 / 1.15 / 0.18`；仍需实车分目标位置复验 |
| 纵向前馈设为 0.55 | 车体加减速会造成可重复的纵向滚球扰动，且需先扣除静态 IMU bias | 保留；它用于动态扰动，不用于修静态偏差 |
| Q6 横向耦合高于 Q4/Q5 | Q6 整圈、带目标保持时转弯扰动更突出；转弯同时存在 X/Y 加速度 | 当前为 Q6 0.50、Q4/Q5 0.25；只可基于含双轴 IMU 的日志继续调整 |
| “增大 Q6 耦合 + 缩短滤波 + 放宽正常角度上限”一起上 | 实车效果变差，无法分辨是哪项造成 | 已撤回；后续禁止多变量同时改 |
| 首秒使用较大角度上限 | 试图救起步误差，却在切回正常上限时形成命令突变 | 已撤回，正式运行限幅保持连续 |

因此当前最重要的未闭环问题不是“再找一套更大的参数”，而是：分别在 Q4、Q5、Q6 的 0、正目标、负目标和出弯段采一轮可确认 mode 的日志，比较最大误差、稳态偏置、饱和时间和进入 ±1 cm 时间。没有这些分段指标，参数改变只是在碰运气。

### 参数调试的强制顺序

1. 确认视觉位置、IMU 轴向、机械角、任务 mode 和 epoch 都可信。

2. 先做 B21 调平并记录静止漂移；若不调平，后续 `Ki` 会吸收机械坡度，得到不可迁移的参数。

3. 对 Q3，先定 `rate`，然后 `Kp`，随后 `Kd`，最后只用少量 `Ki` 消除稳态误差。

4. 对 Q4–Q6，先调底盘软启动和 IMU bias/前馈，再调 `Kp` 和 `Kv` 的响应/阻尼，最后才调 `Ki`。每一步先确认没有饱和。

5. 将“全程最大误差”和“稳态 ±1 cm”分开验收；起步瞬态失败不能用稳态参数硬救，反之亦然。

6. 每次只改一个参数，保留前一个 commit 和一段对应日志；效果变差可立即回退，而不是继续叠加补丁。

## 状态机修复：问题、决策与边界

### 状态机为什么必须有 epoch

TI 和 M33 会独立复位，CAN 又会重传。没有 epoch 时，TI 屏幕已经选 Q3，而 M33 可能还在执行上一轮 Q4/Q5 的 `RUNNING`；同一个 `START` 字节在两边代表不同任务，属于危险的“界面正确、执行对象错误”。

因此任务上下文定义为二元组：`(epoch, mission_id)`。TI 选择任务时递增 `candidate_epoch` 并发送 `PREPARE`；M33 只有回传完全相同的 epoch 和任务后，TI 才接受状态。控制器启动时也记录该二元组，检测到不一致立即停止旧控制，避免旧任务继续对电机下命令。

```text
TI: RESET -> PREPARE(epoch, mission) -> 等 READY -> START
M33: PREPARING -> READY -> START_PENDING -> RUNNING
TI: 仅收到同 epoch/mission 的 RUNNING 才允许底盘进入 Q4–Q6 循迹
```

### 每个修复背后的决策

| 原始故障 | 根因 | 修复决策 | 为什么不是简单放宽条件 |
| --- | --- | --- | --- |
| 只复位 TI 后，M33 还在旧任务，双方永远不同步 | 普通 PREPARE 会拒绝旧 epoch；旧 RUNNING 又不会主动退出 | `RESET` 定义为跨 MCU 恢复命令：先让 M33 受控中止旧上下文，再由重复 RESET/新 PREPARE 建立 TI 的上下文 | 对所有旧 epoch 都接受会让旧 CAN 帧重新激活旧任务 |
| M33 独自复位后，TI 已在重传 START，却一直无法启动 | M33 没有上下文，直接拒绝 START | 无上下文时先用匹配 START 重建 PREPARING，但仍必须经过 READY，再由后续 START 启动 | 直接把第一帧 START 当启动会跳过电机、视觉、IMU 安全门 |
| RESET 一直发导致永远不 READY | 重复 RESET 每次都清空 READY 稳定计时 | 同一 `(epoch, mission)` 下的 RESET 在 PREPARING/READY 幂等；当前 READY 条件连续满足 150 ms 才进入 READY | 取消稳定时间会让单帧视觉/IMU 抖动误触发启动 |
| SW1 一下去就 ABORT，电机参数却很快才到 | ARM 后位置/速度读回尚未刷新，被第一帧检测判为失败 | `START_PENDING` 中等待新鲜机械位置/速度并重试；依然保留准备超时和运动看门狗 | 无条件等待会掩盖断线或电机不响应 |
| Q3 已结束却 LCD 永远 RUNNING | 控制器停止没有映射到状态机终态 | 未通过/超时映射为 CONTROLLED_ABORT，成功映射为 COMPLETED | 仅让电机停下会让 TI 继续按 RUNNING 处理底盘/界面 |
| B21 连续帧重复执行调平/设目标 | CAN 是周期重发，同一动作被反复看作新事件 | 用 `epoch + event_time` 去重；Q3–Q5 作为调平事件，Q6 作为目标锁存事件 | 仅按命令字去重会丢失下一轮真正的新 B21 |
| RESET/PREPARE 偶发丢失、同步卡住 | 与 IMU 遥测共用 TX buffer，关键帧被占满 | 任务 intent 优先于普通遥测，并给相邻两个发送时隙 | 单纯提高发包频率会更容易碰 TX busy |
| SW1 看似要按多次 | 任务状态不新鲜或 IMU MISS 时 TI 合理拒绝 START | TI 将 SW1 锁存最多 5 s，等同 epoch 的 READY 回来后自动提交 START；根因仍需修 IMU 而非绕开 READY | 无条件发 START 会在 M33 NOT_READY 时被拒绝，还可能误使能 |

### 仍须遵守的状态机不变量

- `START` 只能从相同 epoch/任务的 `READY` 进入，绝不直接使能电机。
- Q4–Q6 的底盘只能跟随同一 epoch 的 M33 `RUNNING`；状态超时、中止或任务号变化立即停车。
- Q3 不允许底盘移动；Q2 不依赖 M33/CAN 的 READY。
- M33 的传感器安全门是真实状态，不可为了方便启动删除 IMU、视觉或电机新鲜度检查。
- “电机已停”与“任务已终态”是两件事，必须同时发出终态状态帧。

### 状态机还剩的风险

1. IMU 队列拥塞、视觉 USB 重连仍会让 READY 合理撤销；这是输入链路问题，不能靠状态机强行保持 RUNNING。

2. B21 的“调平”与 Q6 的“目标设置”共用同一个按键，必须由任务号决定含义；现场操作前先看 LCD 任务号和 setup/target 已锁存的状态。

3. 5 s 的 SW1 锁存只是为了跨过短暂 READY 抖动，不是无限等待。若到期仍未启动，要读 READY mask 和 reason，不能继续盲按。

## 对数值日志的最低要求

每段试跑至少记录并检查：

- 任务 `mode` 与 epoch：确保数据属于刚启动的题目，而非旧帧。
- 视觉位置 `x`、目标 `r`、误差 `e=r-x`、球速度：判断是稳态偏置、欠阻尼还是视觉跳变。
- 管道命令角和实际机械角：判断是否饱和或传动/通信没跟上。
- X/Y 加速度和滤波后值：转弯时必须两轴一起看。
- IMU/视觉有效位、UART dropped、队列 high-water、帧计数：先排链路再调控制。
- 底盘软启动阶段、实际速度：把起步尖峰与控制器本身分离。

HBLG 转 CSV 的工具：

```bash
python3 vision/raspberrypi/control_log_to_csv.py input.hblg output.csv --all-sources
```

不要在服务正运行时抢同一 USB 源采集；先停用户服务，单独采集，再恢复服务。否则“日志缺帧”可能只是两个进程抢设备。

## 编译、烧录与复核必坑

1. TI 固件常规构建从 `firmware/mspm0/wit-oled-hardware-spi` 执行 `cmd.exe /d /c build-keil.bat`。旧的 DAPLink 脚本依赖缺失的 `tools/ti-env.bat` 时会失败；已验证可用 pyOCD 或 J-Link 直接烧录。

2. J-Link 烧录后必须确认 `Program/Verify` 成功，并让目标 `go`。仅连接/复位不代表程序正在跑。

3. EdgeTalk M33 与 TI 是两份固件；改 M33 控制器只烧 TI 不会生效，反之亦然。每次变更前先写清“这一行代码属于哪一颗 MCU”。

4. 侧边任务也在改固件时，先 `git status --short`，不要覆盖或暂存无关改动。一次物理试验对应一个小提交，才能退回最后已知可用的参数。

5. 烧录完成不等于验证完成。至少观察一轮：M33 READY、IMU 帧连续、视觉位置可信、按一次 SW1 可以进入正确任务、机械角没有卡在限位。

## 一页现场流程

```text
上电
  -> 看 IMU/视觉/Link 都为 READY
  -> B21 调平（Q3/Q4/Q5 先做；Q6 按当前题目交互确认目标）
  -> 人工放球到可识别位置，确认视觉不是反光
  -> 仅按一次 SW1
  -> 保存这一轮日志并核对 mode/epoch
  -> 先判断：链路 / 状态机 / 视觉 / 执行器 / 控制 哪一域
  -> 只改一个变量，编译烧录（或空闲时下发 Q3 RAM 参数）
  -> 冷启动复跑，记录最大误差和收敛时间
```

把这套顺序守住，调参就会从“感觉不对一直加参数”变成有证据的闭环。尤其是：先确认输入可信、确认没有饱和，再决定调哪一个增益。
