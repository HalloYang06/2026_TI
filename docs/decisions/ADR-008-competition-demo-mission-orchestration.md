# ADR-008：H题现场演示采用MSP意图入口与M33统一任务仲裁

- 状态：Accepted for shadow integration；正式执行器授权仍需单独评审
- 日期：2026-07-31

## 背景

H题的启动按键和不大于2英寸的计时显示装置位于车上，而当前系统包含MSPM0、
EdgeTalk M33/M55、树莓派、RS00和可选NanoPi-M5。现有MSPM0 CAN V1只向M33发送
传感器遥测；M33/M55 IPC与USB控制日志也没有任务编号、任务实例或全局状态。若各设备
根据首次数据、局部按键或本地超时独立判断“任务开始”，会出现重复启动、视频归档错误、
目标位置不一致和一块板已运行而另一块板仍在准备等现场故障。

本决策只冻结任务编排和接口边界，不授权自动使能电机。现有本地底盘调试代码、
`SHADOW_ONLY`和`ACTUATOR_TX=0`边界继续有效，直到相应人工受控验收门通过。

## 决策

1. MSPM0是唯一的操作员意图入口：SW3选择任务，SW1执行任务；其他板不得自行开始
   评分任务。
2. EdgeTalk M33是唯一的分布式任务仲裁器：它汇总MSP、视觉/录像、M55控制器、
   RS00和安全门状态，并发布唯一全局任务状态。
3. 每次SW1有效启动生成一个单调递增的`mission_epoch`。所有CAN、IPC、USB日志、
   视频文件和结果都带同一epoch；重复的START按epoch幂等处理，不得重复解锁或清零。
4. 赛题第1项是常驻视觉录像/显示/回放服务，不占用一个SW3选项。SW3只循环官方
   任务2、3、4、5、6，代码和页面统一使用`Q2..Q6`，不再使用含义不明的
   `TASK1/TASK2/TASK3`作为跨板协议编号。
5. SW1按下的MSPM0本地单调时刻是车载计时显示的起点；M33收到同epoch START后记录
   自己的接收时刻和传播延迟诊断。不得用第一帧视觉、第一条电机命令或底盘真正起步
   的时刻替代按键起点。
6. M33必须在按键前持续计算并下发READY。SW1在READY之外按下只提示缺失条件，
   不排队、不延迟自动启动。条件恢复后必须由操作员重新按SW1。
7. MSP与M33之间增加独立的双向任务控制面；现有200 Hz IMU和100 Hz轮速数据面保持
   不变。任务控制面采用20 Hz状态重发和epoch去重，不能依赖一次CAN边沿。
8. M33/M55之间增加独立任务上下文槽和任务结果槽，不把任务字段硬塞进现有高频
   sensor/control槽的剩余字节。USB返回日志升级并加入任务上下文；树莓派增加录像
   就绪、START/END marker确认和按epoch归档。
9. 任务6在START时由M33锁存最近一小段有效、静止的视觉估计作为目标位置；锁存后
   任一节点不得自行重新取样或把目标重置到中心。
10. NanoPi-M5不进入比赛主链路。它只作为预装同版本视觉服务的冷备机，切换主机后
    必须重新完成SELF_TEST和READY，不能在任务运行中热切换。

## 按键决策

- SW3短按：仅在SELECT、READY或COMPLETED中循环Q2到Q6；切换后进入PREPARING，
  等待新任务的动态READY。
- SW1短按：仅在READY中创建/确认新epoch并启动；运行中短按忽略，防止误触。
- SW1长按1 s可作为非评分状态下的“受控中止”候选，但实施前必须由负责人确认。
  硬件急停始终是直接断开动力，不能由软件长按替代。
- 两键同时按下视为歧义输入，等待全部释放后忽略。

## 结果

- MSP无需运行滚球算法，但必须接收M33状态，才能在车载小屏上显示全局READY、任务号、
  按键起算时间、球位置/目标和完成或故障原因。
- M33将新增任务仲裁模块，并成为唯一可以把M55目标送入正式RS00安全门的节点。
- M55算法输入将明确包含任务ID、epoch、目标位置和任务阶段；相同传感器数据不会因
  不同板的本地状态被解释成不同目标。
- 树莓派在PREPARE阶段打开按epoch命名的录像和日志，并保留预录缓冲；未确认录像可写
  时M33不置READY。
- 任务协议会给1 Mbps Classic CAN增加约1.5%最坏负载，不改变现有高频遥测的ID和频率。

## 不采用的方案

- 不让MSPM0直接广播一次START后所有节点自行运行：一次帧可能丢失，且无法证明所有
  节点使用了同一任务和目标。
- 不让树莓派或M55成为任务主控：车载按键只在MSP，USB/算法节点重启时也不应产生新的
  操作员意图。
- 不为每道题设置独立固件：现场换固件增加版本漂移和烧录失误；采用一套固件、配置化
  任务表和可审计epoch。
- 不把NanoPi和树莓派同时放进控制链：双视觉主机的主备仲裁收益低于新增的状态复杂度。
