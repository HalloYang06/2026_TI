# ADR-009：评分任务由EdgeTalk集中编排，算法按调用层分离

- 状态：Accepted
- 日期：2026-07-31

## 背景

Q2～Q6同时使用MSPM0底盘、EdgeTalk M33/M55、树莓派和RS00。若四端都写一套按Q号
分支的状态机，同一任务会出现多个阶段真相；若把任务、估计、控制和驱动写进一个函数，
又无法独立仿真、回放和验证安全门。

## 决策

1. EdgeTalk M33持有绝大多数题目逻辑，也是唯一的Q2～Q6阶段状态机所有者。每道题的
   阶段切换、deadline、完成/失败谓词和跨节点动作都在M33执行。
2. M55不再复制五道题的状态机。M33通过任务IPC下发显式的`target_position`、控制模式、
   限幅、phase和epoch；M55只运行通用状态估计和滚球控制，并回报估计、稳定判据和故障。
3. MSP不判断全局任务完成。它只提供SW3/SW1操作入口、通用底盘动作执行器、A/B/丢线/
   停稳事件和失联本地停车。M33用通用动作命令驱动MSP，不让MSP按Q号复制任务流程。
4. Pi不写Q2～Q6状态机。它持续提供视觉、录像、marker ACK和回放服务；Q号/epoch仅用于
   配置、显示、日志和文件归档。
5. 通用算法只接收显式`config/input/state`并返回`output/status`，禁止读取全局Q号，也
   禁止调用RTOS、HAL、CAN、USB、LVGL或执行器发送函数。题目专用M33状态机只组合公共
   服务，不重新实现滤波、估计、LQR/LQI、底盘闭环或录像。
6. 处理器内使用普通函数调用；跨M33/M55只用带epoch的IPC；跨M33/MSP只用CAN；跨
   M33/Pi只用USB。文档中的箭头不得被实现成跨核直接函数调用。
7. 正式执行器路径固定为“M55控制结果 → IPC → M33安全门 → RS00适配器”。任何任务
   函数、公共算法或MSP/Pi代码都不能绕过M33安全门发送电机命令。

## 调用关系

完整函数级调用链、数据结构、Q2～Q6专用入口和禁止依赖见
[`mission-code-layout.md`](../architecture/mission-code-layout.md)。目录只用于承载这些代码
层，核心约束是调用方向和状态所有权。

## 迁移策略

现有四端shadow链路不做一次性批量搬迁。先把当前`hball_mission_tick()`演进为M33任务
运行时入口，再引入任务IPC和通用底盘动作协议；每一步保持`ACTUATOR_TX=0`且可用host
测试证明。现有M55 `hball_control_pipeline_step()`继续作为通用控制入口，先改为从任务
context读取目标，不增加Q号分支。

## 结果

- M33是唯一任务阶段真相，M55/MSP/Pi不会各自“认为已经进入下一阶段”。
- Q3的`+5 cm → -5 cm`和Q6的一次目标锁存由M33决定；M55只跟踪明确目标。
- 公共算法可独立仿真和测试，同一控制器服务Q2～Q6而不复制。
- 驱动层只搬运数据，安全门仍是执行器唯一出口。

## 不采用的方案

- 不在四端分别创建Q2～Q6完整状态机。
- 不让M55根据Q号自行改变目标或阶段；它只执行M33下发的context。
- 不让MSP用本地`TASK1/TASK2/TASK3`决定比赛任务完成。
- 不把安全限幅藏进题目函数或控制器末尾；M33安全门单独复核。
