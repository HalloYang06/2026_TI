# ADR-001：车载滚球三板控制边界与控制算法

## 状态

实验性采用，等待实物标定和重复测试

## 日期

2026-07-29

## 背景

H 题要求轮式小车只用红外光电循迹，在 25 cm PPR 凹槽内用摄像头检测直径约 1 cm 的钢球，并在静止位置切换和小车整圈运动时把钢球位置误差保持在 1 cm 内。现有可用主控包括天猛星 MSPM0G3507、树莓派和 Infineon EdgeTalk；不强制使用 F407 或 NanoPi M5。

系统同时存在 60 Hz 延迟视觉、车体加减速、俯仰、转弯角速度、摆杆无刷角度反馈、摩擦、冲击和多处理器通信。将所有量直接接入一个同频 PID 会让快速电机环受慢视觉链路限制。

## 决策

### 板级边界

- 天猛星 MSPM0G3507 负责红外循迹、底盘速度/差速控制、IMU UART DMA 采集、时间戳和 200 Hz 状态包。
- 树莓派负责 60 Hz 摄像头采集、钢球坐标/置信度/采集时间戳和比赛要求的视频显示存储。控制链只发送结构化位置结果，不传整帧图像给 EdgeTalk。
- EdgeTalk 负责全部滚球控制：200 Hz 状态观测与 LQG、1 kHz 摆杆角度环，以及在硬件支持时的 20 kHz 无刷 FOC。
- F407 和 NanoPi M5 不进入正式链路，保留为故障替换或离线工具，避免额外同步点和供电风险。

### 算法边界

- 选用“非线性可测扰动前馈 + 三状态增广 LQR + 延迟 Kalman 观测器”，而不是纯 PID、纯 LQR 或在线 MPC。
- 钢球位置和估计球速构成外层反馈；车体纵向/横向加速度、俯仰和偏航角速度用于模型预测及前馈；无刷编码器角度只闭合快速摆杆内环。
- 球速由 5 帧带时间戳位置做二次最小二乘拟合，再作为观测量融合，禁止直接用相邻两帧差分驱动控制。
- 视觉使用 4σ 创新门限，拒绝孤立反光离群点；连续拒帧时膨胀位置协方差以在约 6 帧内恢复锁定。
- 摆杆目标限制在 `+-4 deg`，目标变化率限制为 `80 deg/s`。LQR 增益固定按标称 25 ms 执行器模型计算，实际执行器变慢不得在验证时偷偷重整定。

### 通信和频率

- IMU UART 采用 `460800` 或 `921600 bit/s`、DMA、二进制定长帧、单调时间戳、序号和 CRC；1 kHz 读取、200 Hz 上送。
- MSPM0 循迹采样 1 kHz、底盘速度环 500 Hz、向 EdgeTalk 状态发布 200 Hz。
- 树莓派视觉 60 Hz；EdgeTalk LQG 200 Hz、摆杆角度环 1 kHz、FOC 20 kHz。
- 任一状态包丢失时短时保持最近值；超过验证得到的超时阈值后停止增加小车速度并进入安全降级，不继续使用无期限旧数据。

## 备选方案

### 双环 PID

实现简单，适合作为台架备用控制器。但摄像头只有 60 Hz 且存在 33~60 ms 延迟，直接位置 PID 的微分项容易放大像素噪声，转弯和加减速只能依靠误差出现后再纠正，因此不作为得分主方案。

### 在线非线性 MPC

可以显式处理摆角、摆速和位置约束，但需要在线优化器、最坏执行时间证明和更多实物模型参数。当前 EdgeTalk 需要同时承担 1 kHz 角度环和 FOC，比赛周期内收益不足以抵消实现风险，保留为离线对照方案。

### 全部控制放在树莓派

视觉接口方便，但 Linux 调度抖动不适合 1 kHz 摆杆角度环和 20 kHz FOC；拒绝采用。

### 增加 F407 或 NanoPi M5

可以扩展算力，但会增加供电、时钟同步、协议和故障点。当前三板已覆盖实时底盘、视觉和滚球控制，拒绝为了“把板都用上”而加入正式链路。

## 后果

- 必须做跨板时间同步并在每个数据包中保留采集时间戳，接收时间不能替代采集时间。
- 必须先标定相机噪声/延迟、执行器时常/纯延迟/增益/死区、摆杆水平零点和摩擦，再把实测值回填 `experiments/h_ball_control_sim`。
- 软件压力测试的 2 级共 12/12 通过，峰值最坏 6.48 mm；3 级首次失效，说明实物验收首先瞄准 2 级包络，而不是用单次成功证明可靠。
- 仿真仍为未验证原型，保留在 `experiments/`。实物验证前不得提升为正式控制实现。
- 自动测试不得解锁无刷或底盘。台架测试必须车轮架空、动力断开或限流、硬件急停、操作员保留断电接管。
