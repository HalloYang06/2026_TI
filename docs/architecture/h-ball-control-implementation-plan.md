# H题滚球控制实施与审计指南

Date: 2026-07-31

Status: implementation plan; actuator output remains disabled

## 1. 结论

三板通信链路已经打通，但当前软件还不能闭环驱动RS00。最主要的原因不是LQR参数
不够大，而是数据的源时间、坐标系和机构角映射尚未闭合。

当前必须保持：

```text
MOTOR_COMMAND_TX=0
ACTUATOR_TX=0
MSPM0 heartbeat ESTOP_ACTIVE=1
```

达到部署条件前，现有M55 `hball_lqg`只作为旧模型shadow回归，不能把其输出接到电机。

## 2. 已冻结的机械和题目条件

| 项目 | 当前值 | 含义 |
|---|---:|---|
| 水管物理长度 | 250 mm | 与CB和实际挡边间距不同 |
| 视觉零点到物理挡边 | 左右各112 mm | 挡边间距224 mm；球心极限还需扣除半径 |
| 视觉零点到C轴 | 155 mm | 向C运动为负，`x_C=-155 mm` |
| 主动曲柄OA | 35.0 mm | RS00输出轴到主动杆端 |
| 蓝色连杆AB | 55.5 mm | 主动杆端到水管连接点 |
| 水管摇杆CB | 300.1 mm | 右侧合页C到左侧蓝杆连接点B |
| RS00轴O高度 | 38 mm | 用户实测 |
| 合页轴C高度 | 93 mm | 用户实测 |
| O-C水平距离 | 285 mm | O在C左侧 |
| 水管水平时B相对O水平偏置 | -15.1 mm | B在O左侧 |
| 正常/恢复/软件硬限位 | ±4° / ±5.5° / ±6° | 新机构的三个安全层次 |
| 相机 | 100 Hz目标 | 必须统计唯一帧序号，重复帧不算 |
| 位置误差要求 | ≤10 mm | 必须说明评分时间窗，不能把恢复过程伪装成全程通过 |

C是右侧固定合页，水管水平时`C->B`向左；O位于C左侧285 mm、低55 mm。若水管外径约
50 mm且C轴与水管中心轴重合，管底约68 mm，满足“台面不低于50 mm”。MATLAB对当前
`OA/AB/CB/OC`闭环的分析表明：`±6°`全部可达，RS00相对水平零位约需
`-57.00°`到`+70.68°`，最小`|dtheta/dq|=0.0467`，最差换算约`21.43`。旧的
`±8°/1.2 rad/s`基线不能沿用；孔位或轴高再变化时必须重新运行
`analyze_two_link_mechanism.m`。

树莓派与控制器统一使用`x_cam`：零点为视觉零点，向C为负，远离C为正。钢球球心到
C轴的沿管力臂为`s_C=0.155+x_cam`（SI单位）。物理挡边位于`±0.112 m`，控制限位
必须根据实测钢球半径再向内缩，并另外保留制动安全区。

3.0 m/s²是仿真中故意超出机构稳态补偿能力的轴向加速度脉冲，不是小车速度，
更不是要求小车跑到3 m/s。正常车辆对照使用0.45 m/s²正弦轴向加速度；启动/硬制动
测试包含+0.90/-1.50 m/s²短时事件。最终速度上限要由地图直线长度、制动距离、转弯
半径和实测轮胎抓地力计算。

## 4. 数据格式审计

### 4.1 MSPM0 CAN

线协议的ID、DLC、小端和毫单位设计正确，Classic CAN自身已有链路CRC，不需要再挤入
应用CRC。M33对标准/扩展帧、远程帧、DLC、未知ID、重复、乱序、跳号和重启的检查也
是正确方向。

| ID | 当前CAN调度 | 当前源语义 | 部署判断 |
|---:|---:|---|---|
| `0x080` | 20 Hz | uptime、状态；急停始终置位 | 安全锁有效，正式急停输入尚未映射 |
| `0x100` | 200 Hz | JY901S `0x51`源序号 + 加速度 | 实测源帧约199.6 Hz |
| `0x101` | 200 Hz | WIT `0x52`源序号 + 角速度 | 源序号已修正，当前整数dps量化偏粗 |
| `0x102` | 100 Hz | 左/右/车体速度 | 轮周长为0，当前值全0，不可用于算法 |
| `0x103` | 200 Hz | WIT `0x53`源序号 + 姿态 | 协议文档已从错误的100 Hz修正 |

当前JY901S UART为115200 bit/s。修复DMA流式解析并按官方`RSW=0x000E`开启
三类报告后，10 s内`0x51/0x52/0x53`各`+1996`（约199.6 Hz），校验/未知帧增量为0。
只有收到新源帧时相应序号才变化，重复CAN镜像不刷新M33 age。

V1仍缺少统一IMU epoch和源时间。正式方案按
[`MSPM0_CAN_TELEMETRY_V2_PROPOSAL`](../../shared/protocol/MSPM0_CAN_TELEMETRY_V2_PROPOSAL.md)
增加`0x104`元数据，或在经过实测后冻结等价合同。

### 4.2 WIT解析器剩余问题

1. DMA块清空前没有保存1到10字节残帧，非对齐边界可能丢失一帧。
2. UART ISR执行校验、浮点换算和多字段写入；SysTick同时做浮点SI换算和MCAN排队。
3. 原始角速度先截断成整数dps，低速分辨率约17.45 mrad/s，可能不够做转弯前馈。
4. 尚无加速度/角速度/姿态各自的校验失败、饱和、源时刻和完整组统计。
5. `IMU_VALID`虽已要求三类分别新鲜，但100 ms门限只是源健康门；M33控制门仍应使用
   更严格的源age。

三类200 Hz已验收；EdgeTalk心跳置`IMU_VALID`，统一快照`imu_age=4 ms`。

### 4.3 视觉数据

64字节固定帧、CRC32C、序号、有限值/range检查和坏帧重同步设计正确。当前不足：

- C++默认已统一为100 Hz，但必须读取相机实际返回率，不能只相信`CAP_PROP_FPS`设置成功。
- `capture_time_us`目前是`camera.read()`返回后的Linux单调时刻，不是曝光中点。
- 树莓派和M33尚无时钟同步，M55当前使用USB接收age做近似，不是真正OOSM。
- 真实桥接的`confidence=0.85`是常数；曝光稳定和轮廓圆度也尚无真实输出。
- 每帧在采集线程中编码原图和标注图两个JPEG，可能挤占100 Hz处理预算，应实测无观看者
  和有观看者两种P95，必要时把图传编码移到低优先级线程并丢旧帧。

2026-07-31模板匹配/投影标定版本部署后，通过树莓派只读HTTP接口静置采样15.026 s：
收到1739帧，按`capture_time_us`去重后仍为1739帧、`found=true`为1739/1739，有效率
115.731 Hz。位置标准差`0.025661 cm=0.25661 mm`，相对中位数P95绝对偏差
`0.056805 cm=0.56805 mm`；中心x标准差`0.4677 px`。图像处理耗时中位1.380 ms、
P95 1.442 ms、最大1.591 ms，分辨率640x480。当前Simulink的视觉噪声标准差仍保守取
1.5 mm，因为静态重复性不包含动态运动真值误差、曝光延迟和车辆振动。

相机吞吐和静态重复性足够100 Hz，但仍不能替代动态定位精度验收：服务上报半径固定10 px、
面积固定`pi*10^2`，桥接confidence仍是常数。实机ROI约`[59,199,538,60]`，已与当前仓库
四点透视区域对齐。正式验收还需保存逐帧ROI原图，做标尺小位移、遮挡/反光和动态延迟试验。

### 4.4 RS00和机构反馈

当前M33能解析RS00扩展反馈并已只读验证Get_ID，但还没有完成：

- 250–500 Hz连续反馈率实测；
- RS00零位、方向、单圈回绕和故障位标定；
- 电机角`q`到水管角`theta`的四杆正解；
- 水管目标角到电机目标角的连续分支逆解；
- 雅可比、跟随误差、温度/电流/速度限制；
- CSP发送适配器。

现有`hball_control_pipeline.c`直接把`motor_angle_rad`当作`beam_angle_rad`，对当前两连杆
机构是错误的，所以只能shadow。

## 5. 坐标和IMU预处理合同

正式算法只接受车辆坐标系：

```text
+X_vehicle = 水管正方向
+Y_vehicle = 车辆左侧
+Z_vehicle = 向上
positive pipe angle = 球沿 +X 加速
positive ball position = 与 +X 相同
```

必须用一个固定的3x3带符号置换矩阵把IMU板坐标变到车辆坐标，矩阵、安装朝向和固件
版本写入日志。禁止在前馈、显示和控制器各处零散地改符号。

IMU安装在车身上是当前方案的预期做法：它负责测量车身俯仰和底座加速度，不负责测量
水管相对车身的角度。相对水管角由RS00编码器`q`经过四杆正解得到，世界系水管角为：

```text
theta_world = theta_linkage(q) + pitch_vehicle
```

因此车身IMU可以在相机看到钢球偏移之前做车辆扰动前馈，但不能观测连杆回差、支架变形
或水管相对车身的真实偏角。若这些误差超过标定预算，应在C轴增加直接角度编码器；不应
把车身IMU当作水管角传感器。

加速度计给出的是specific force，不能一边直接把原始`ax`当车辆惯性加速度，一边又用
pitch加入重力项，否则会重复补偿重力。部署输入`a_vehicle_x`必须明确为经过姿态旋转、
静态偏置和重力处理后的车辆轴向加速度；用静止水平、静止±已知坡度和直线加速三组
实验验证符号与幅值。

## 6. 目标算法

### 6.1 非线性对象和前馈

在纯滚动小角度附近：

```text
x_ddot ≈ (5/7) g theta_pipe - a_vehicle_x + d
```

完整仿真保留正弦、滚动/滑动、Stribeck摩擦、滚阻、黏性/二次阻力、垂向冲击和机构
动态。前馈只补偿可靠可测的车辆加速度与pitch：

```text
theta_ff = a_vehicle_x/g - pitch - d_hat/((5/7)g)
```

`d_hat`补偿必须低带宽和限幅，不能把视觉延迟造成的创新全部当作新扰动。

### 6.2 估计器和控制器是两套不同状态

估计器状态：

```text
x_hat_kf = [position, velocity, lumped_acceleration_disturbance]
```

LQI反馈状态：

```text
x_lqi = [position_error, estimated_velocity, integral(position_error)]
```

二者第三项不同。旧Python/C固件使用的LQR第三项是
`actual_pipe_angle - feedforward_angle`，不能把增益
`[14.56338, 3.31547, 0.58093]`套到新LQI的积分状态。

### 6.3 真正OOSM

M55以5 ms固定周期保存至少32个历史节点，覆盖160 ms：

```text
node = {
  time, state[3], covariance[3x3],
  applied_pipe_angle, processed_vehicle_input
}
```

新视觉帧到达时：

1. 把曝光时刻换算到M55时间域；
2. 找到不晚于曝光时刻的历史节点；
3. 在该节点做位置创新门和Kalman更新；
4. 用保存的每周期输入逐节点重放到当前；
5. 每个视觉sequence只消费一次。

当前C实现把旧位置用当前速度/加速度外推到现在，Simulink实现也使用固定延迟观测矩阵；
二者都不是完整历史回放，只能作为过渡回归。

### 6.4 LQI、端部保护和两连杆

普通控制：

```text
theta_cmd = theta_ff - [Kx Kv Ki] *
            [position_error, velocity_hat, integral_error]
```

顺序必须是：

1. 视觉创新门与状态估计；
2. 车辆/扰动前馈；
3. LQI和条件积分抗饱和；
4. 根据位置、向外速度和制动距离判断端部恢复；
5. 正常±4°、恢复±5.5°、硬限±6°和0.35 rad/s水管角斜率；
6. 四杆逆解得到RS00电机目标角；
7. M33检查分支连续性、雅可比、RS00 age/故障/跟随误差；
8. 只有人工授权的正式固件才允许发CSP。

LADRC可以作为扰动估计对照，但不建议替换整个首版方案。高带宽ESO会把30–50 ms视觉
延迟误认为快速扰动并放大到滑管上；推荐保留KF的`d_hat`低带宽补偿，再用同一日志离线
比较LADRC。MPC在加入角度/速度/端部约束方面有优势，但首版算力和验证复杂度更高，等
LQI实车数据稳定后再作为上层优化，不作为首个可动版本。

## 7. 实现阶段和验收门

### 阶段0：数据真实

- 统计WIT三类源帧率、校验失败、最大间隔和同步差。
- 轮周长、每圈计数、左右极性完成标定，`0x102`不再全0。
- 相机100 Hz唯一帧率、P50/P95/P99处理和端到端延迟完成测量。
- 冻结IMU轴矩阵、加速度定义、视觉正方向和所有零点。

未通过时只允许记录，不进入算法调参。

### 阶段1：主机回放

- 定义统一二进制日志：源时刻、接收时刻、序号、valid、原始量、变换后量。
- 用真实日志跑Python、Simulink和M55 host实现，对齐每一步状态。
- 证明重复帧不刷新age、乱序不覆盖、超时能降级。

### 阶段2：M55 shadow算法

- 实现32节点OOSM历史回放。
- 把估计器状态和LQI状态类型分开命名。
- 接入四杆正/逆解和连续分支检查。
- 所有输出带`SHADOW_ONLY`，M33继续`ACTUATOR_TX=0`。

### 阶段3：HIL

- 用记录回放器模拟100 Hz视觉、真实IMU间隔和RS00反馈。
- 注入丢帧、重复、乱序、时钟跳变、CAN bus-off、USB重连、NaN、饱和和重启。
- HIL运行至少30 min，无错误解锁、无旧数据刷新、无历史缓冲越界。

### 阶段4：无球机构台架

- 限流电源、动力隔离、硬急停、操作者可立即断电。
- 人工使能后只做±1°、±2°、±3°阶跃。
- 辨识纯延迟、5–95%上升时间、死区、回差、最大水管角速度和电机温升。
- 比较空载/带固定等效载荷，更新Simulink机构与RS00参数。

### 阶段5：静止滚球

- 先中心保持，再`0 -> +5 cm -> -5 cm`。
- 评分稳定段误差≤10 mm，同时报告RMS、峰值、超调、稳定时间和掉帧。
- 逐级开放正常±4°，恢复到±5.5°只有在端部保护验证后开放。

### 阶段6：小车

- 架空底盘重放；
- 低速直线；
- 低速启停；
- 低速转弯；
- 最后才是完整地图。

每级只增加一个扰动维度，失败后把实测日志回填Simulink，不通过盲目增加增益掩盖。

## 8. 当前仿真能证明什么

MATLAB/Simulink R2025b当前结果：

| 场景 | 结果 | 可声称 |
|---|---|---|
| 100 Hz正常车辆、初始5 mm | RMS 2.344 mm，峰值5.216 mm | 数值模型内严格1 cm通过 |
| 100 Hz启停/制动/坑洼、初始5 mm | RMS 21.453 mm，峰值60.559 mm | 当前包线内严格1 cm失败 |
| 可行组合、初始25 mm | 优化RMS 10.618 mm、峰值25.000 mm；仅KF-LQI RMS 13.462 mm | 两者机械安全，不是全程1 cm |
| 超新机构包线组合 | RMS 44.107 mm、峰值94.311 mm、滑移148.278 mm/s，失败 | 机构/控制能力边界 |
| 3.0 m/s²轴向超限脉冲 | RMS 80.457 mm、峰值115.003 mm、滑移100.310 mm/s，失败 | 机构/控制能力边界 |

仿真能够复现实物模型假设、做消融和找失效包络；它不能自动包含未知回差、线束弹性、
相机曝光延迟、WIT内部滤波、真实PVC表面污染和打滑。可靠性来自“实测参数—回填模型—
HIL—逐级实车”的闭环，不来自一次仿真通过。

## 9. 后续AI协作规则

新AI线程先按顺序读取：

1. 本文；
2. `docs/decisions/ADR-006-rs00-two-link-deployment-baseline.md`；
3. `shared/protocol/MSPM0_CAN_TELEMETRY_V1.md`和V2提案；
4. `shared/protocol/VISION_MEASUREMENT_V1.md`；
5. `experiments/h_ball_control_simulink/README.md`；
6. `docs/ai-handoffs/h-ball-control.md`。

开始改代码前先报告当前处于哪个阶段、缺哪个验收证据。不得：

- 把CAN镜像率当作IMU源采样率；
- 把相机出队时刻当曝光中点；
- 把电机角直接当水管角；
- 混淆KF扰动状态和LQI积分状态；
- 把恢复测试写成全程1 cm通过；
- 在自动测试、烧录或HIL中启用电机/自主运动；
- 未实测就把旧LQR或Simulink增益烧入正式固件。

每次交付必须附：

- 改动文件；
- 使用/假定的机械、传感器和时序参数；
- host测试结果；
- 尚未验证的硬件风险；
- 下一项只读或人工受控硬件验收步骤。
